## P007 queued-overflow sequencing and host latency (2026-11-19 candidate, NOT RUN until Windows CI)

**Defect identified by source analysis:** The earlier queue-overflow panic ran immediately in the feeder, even though accepted MIDI NoteOns remained scheduled in the queue at future frames. The panic could therefore execute **before** those earlier accepted notes, leaving them sounding. Overload lacked a real-host recovery test. Separately `getLatencySamples()` still returned zero despite deliberately scheduling every MIDI message 2,784 native frames into the future (2,304 lead + 480 worker guard).

**Proposed correction:** Once queue capacity is exceeded, latch recovery and reject additional input until the feeder has dispatched the complete accepted backlog. The feeder only then inserts all-channel CC123 and CC120 through the firmware input, then admits new events. An excess raw MIDI length or scratch-array overflow requests the same fail-closed recovery *after* the valid accepted prefix is enqueued. Release-active standalone test asserts all 8 queued messages survive, the 9th triggers recovery, intermediate pushes reject, panic cannot overtake the backlog, and fresh input works after draining. A dedicated test-only mutant tries premature recovery and must FAIL with return 14. The real VST3 host test sends 1 NoteOn + 520 MIDI clock messages + dropped NoteOff, asserts the worker's recovery marker comes after exactly 511 accepted clocks, and verifies a post-recovery NoteOn/Off pair. These probes verify firmare MIDI dispatch ordering; they **do not** independently prove the physical envelopes have decayed to silence.

**Latency contract:** Report the *known scheduling component* of the producer's host-facing delay, rounded from 2,784 frames at native 48 kHz: 44.1k → 2,558 samples; 48k → 2,784; 96k → 5,568. This is a minimum producer-delay estimate and not a claim that original firmware UART/poll and analog/audio output have zero additional delay. The real host probe checks these three values during setupProcessing. Exact sampled PCM-onset latency and host PDC acceptance remain OPEN.
