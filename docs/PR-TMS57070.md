## Title

Emulator: four behaviours inferred from the Oberheim OB-12 DSP firmware

## Description

Hello, and thank you for this project: the wiki, the IDA module and the emulator made it possible
to run the OB-12's five TMS57070 chips from their real firmware (Viscount, DSP v1.11, CPU v1.52).

Running that firmware showed four places where the emulator's behaviour breaks it. Each change
below is **inferred from what the firmware needs. None is checked on silicon.** If you can test
them on real hardware, that would settle it, and any of them can be dropped from this PR.

Word addresses are PMEM addresses in the OB-12 voice program unless noted.

### 1. Secondaries 28-2B act after the primary of the same word

The voice program walks three tables with stride 0x15:
- 01A: `M1 = -(2 x tick) x C007`, with C007 = AC0000, which is 1.3125 per tick.
- 01C sets MAC output shift 4 with secondary 29.
- 01D `23A92027` adds M1 to C027 and sets output shift 0 in the same word.
- 1.3125 x 16 = 21 = 0x15, the spacing of the tables at C045, C05A, C06F.

So the add has to see shift 4. With the secondary first it sees shift 0, steps by 1 and the
program overwrites its own tables. Only 29 is proven by this; 28, 2A and 2B follow by analogy.

### 2. Primary 3E with flag 8 is a compare, flags only

The hole marked `idk`. 091 `3E801A07` tests a tick counter in D07 against C00B = 3, and 092 is a
conditional that uses the result. Each sample then selects a voice slot, index = tick, or tick
minus 3 from tick 3 on, and 098-09B load a pointer pair from C11C-C11E.

Without the compare, the flag is stale, the index reaches 3-5, the pair comes from C11F-C121, and
later stores go through CA over C003, C00D, C068 and others. With it, the pointers cycle
11C, 11D, 11E and the tables survive.

### 3. Secondaries 04, 05, 06, 08, 09 land two steps later, like C1-C5

The source is read at once and the register changes two steps later:
- 127 loads DA1, and 128 must still read D050 through the old DA1. 120-123 and 128-12B are the
  same filter section, one on D04F and one on D050.
- 11E loads DA0, and the next word must still read D09C through the old DA0. Landing at once
  makes the filter read itself.
- Pairs spaced exactly two apart: 0A7 to 0A9, 099 to 09B, 020 to 022.

Tried and rejected: acting right after the primary. Secondary 04 then reads the new ACC at 109.

### 4. Primaries 43, 47, 4B, 4F: low MAC word, unsigned, product 24 bits down

**Retracted locally, after PR #3 was sent.** Later work contradicts this: all five uses are paired with a secondary on the C bus and follow a multiply by C, and DMEM times the held C word brings back the right channel. See docs/HARDWARE.md, "Primary 43 keeps the last C". Corrected upstream 2026-11-07, see docs/PR3-CORRECTION.md.

Used at 0DD, 154, 1BF in the voice programs and at 0E8, 166 in the program for the fifth chip.
It looks like the low half of a double precision multiply. Taking the low word as signed at
full scale made D0AD jump between saturated values, and as saturation is off from 0E2 that
wrapped into noise. Measured on the summed voice bus, note C3:

| Model | Autocorrelation at the pitch period |
|---|---|
| Signed, full scale | 0.47 |
| Unsigned, full scale | 0.95 |
| Unsigned, 24 bits down | 0.996 |

## Result with all four

With these, and the items under "Not in this PR", which the OB-12 harness also applies, the
instrument plays from unmodified firmware. Notes reach the output at the right
pitch, 130.7 Hz and 261.4 Hz an octave apart, spectral flatness 0.005 and 0.003, a three note
chord shows its three pitches, and idle output is exactly 0.

## Verification

A separate core written for the OB-12 project implements the same four behaviours as options.
This patch was compared with it at every step: PC, ACC, MACC upper word, CR1, XRD, DA, CA, all of
DMEM and CMEM.
- 5 programs with loaded CMEM and 3 with the CMEM of a playing instrument, test sine inputs.
- 81.92M steps identical, 20000 frames per case, failures 0.

Before the patch, the same harness with these options off matched this repository's 70357c3 for
81.92M steps. So the patch changes only what is described above, as far as this test reaches.

The harness is not part of this PR, and the firmware is not included.

## Not in this PR

Findings with weaker evidence, offered for discussion:
- **Secondary 34** is the noise source: with the OB-12's Noise slider up and 34 storing a random
  word, the output is true noise, and without it silent. The real sequence and level are unknown.
- **Secondaries 0C, 0D, 0E with flag 4** appear to write DMEM to AX1-3. Without this the chips
  produce no output at all in the OB-12. It could be a follow-up PR if you want it.
- **DMEM ring.** The OB-12 needs a true ring over 00..DCIRC, cells above fixed, and a lock delay
  after 2E.
- **1FC with a zero divisor.** Idle voices needed a guard. This one is a guess.
